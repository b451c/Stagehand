# ReaPack distribution

Stagehand ships as one ReaPack package ("Stagehand", category `Stagehand`) from a public repository index.

## Layout
- `index.xml` at the repository root - the repository index users import into ReaPack
  (`https://raw.githubusercontent.com/b451c/Stagehand/main/index.xml`), generated by `reapack/build_index.py`.
- The package files live under `Stagehand/` at the repository root; the main action `Stagehand/Stagehand.lua` carries the
  ReaPack header (`@description`, `@version`, `@author`, `@provides`, `@changelog`, `@link`, `@about`).
- Every file the package needs is listed in `@provides` of the main action (module launchers, `stagehand/**/*.lua`,
  `stagehand/presets/*.json`, optional fonts), so a fresh install from the index is complete.

## Versioning
Semantic versions `MAJOR.MINOR.PATCH`; pre-releases `1.0.0-beta.N` (ReaPack shows them only with pre-releases enabled).
Git tags `vX.Y.Z` on `main`; `CHANGELOG.md` at the root is the source of the `@changelog` block of each release.

## The index generator
`python3 reapack/build_index.py [--check] [--commit SHA | --url-base URL]` reads the header of `Stagehand/Stagehand.lua`,
expands `@provides` (globs against the package folder), refuses when a provided file is missing OR a file in the folder
is not provided (a forgotten module breaks a fresh install), and writes `index.xml` (package `Stagehand.lua`, category
`Stagehand`, the launchers as `main` actions, `@about` as RTF, `@link` as website links, `@changelog` per version).
The GitHub Actions workflow `.github/workflows/reapack.yml` runs it on every push to `main` with `--commit $GITHUB_SHA`
so the source URLs pin the commit, and commits the index back (`[skip ci]`). Standard library only; no Ruby.

## Release procedure
1. Static gates green (`tools/check_lua_order.py`, `tools/check_i18n.py`, `tools/gen_config_reference.lua --check`,
   `tools/gen_guide.py --check`); every self-test scenario green on Linux, Windows and macOS.
2. `@version` in `Stagehand/Stagehand.lua`, the `Unreleased` section of `CHANGELOG.md` under the version, the
   `@changelog` block summarised from it.
3. `python3 reapack/build_index.py --check`, then a fresh-install test: serve the repository over HTTP
   (`build_index.py --url-base http://<host>:<port>`), import that index with ReaPack into a clean REAPER
   (`reaper.ReaPack_AddSetRepository` + `ReaPack_ProcessQueue`) and run the installed action.
4. Commit, tag `vX.Y.Z`, push; the workflow writes the final `index.xml`; GitHub Pages serves `docs/` (Settings >
   Pages > Deploy from a branch > main, /docs) so `docs/guide.html` is the user guide URL.
5. Forum post from `docs/forum-post-draft.md` (ASCII hyphens) with the video link.

## Dependencies declared to the user
- ReaImGui (required, ReaTeam Extensions repository, installed through ReaPack) - the app refuses to start without it and
  says how to install it.
- js_ReaScriptAPI (optional: glow overlay, screen layout, overview capture).
- SWS (optional: a few convenience actions).
